# Работа с панелью

Установка панели, подключение нод и обновления описаны в [руководстве по эксплуатации](operations.md).

## Ноды и подключения

1. В разделе **Ноды** создайте запись для каждого VPN-сервера. Скопируйте **Команду установки ноды** и выполните её на соответствующем Ubuntu-хосте с `curl` и правами `sudo`. Публичный адрес можно указать при создании или определить автоматически.
2. Дождитесь появления ноды в панели. На её странице нажмите **Создать интерфейс** и выберите WireGuard или AmneziaWG. Укажите подсеть туннеля и UDP-порт. Используйте разные клиентские подсети на интерфейсах, чтобы маршруты между нодами однозначно определяли назначение.
3. Проверьте опубликованный адрес и UDP-порт. Они попадут в клиентские конфигурации. Для AmneziaWG заранее выберите версию профиля, которую поддерживает приложение пользователя. Смена версии на работающем интерфейсе может потребовать переимпорта конфигов.

## Пользователи и устройства

Создайте пользователя и добавьте ему устройство. Выберите ноду и интерфейс, сформируйте профиль и передайте пользователю конфиг или QR-код. Для теста импортируйте профиль на устройстве, подключитесь и убедитесь, что панель показывает свежий handshake и трафик.

У одного пользователя могут быть несколько устройств, а устройство можно развернуть на нескольких нодах. Удаление или блокировка устройства применяется при очередной синхронизации соответствующей ноды.

## Подписки и хранилище ключей

Откройте **Настройки → Конфиги клиентов → Шифрование** и настройте хранилище. Сохраните ключ шифрования отдельно, например в менеджере паролей. Он позволяет открыть хранилище после серверного сброса пароля. Создание конфигураций и работа с хранилищем в браузере требуют HTTPS.

В **Настройки → Подписки** включите сервис. Откройте карточку пользователя и создайте персональную ссылку. По ней пользователь получает сохранённые конфигурации, ссылки импорта и QR-коды своих устройств. Передавайте URL целиком, вместе с фрагментом после `#`, и обращайтесь с ним как с учётными данными. При необходимости ссылку можно отозвать и выпустить заново.

## TURN и VK Звонки

1. На странице ноды откройте настройку TURN-прокси и выберите **FreeTurn** или **WINGS-N**. Укажите VPN-интерфейс назначения и доступный UDP-порт прокси. Дождитесь, пока прокси запустится и его статус появится в панели.
2. Добавьте ссылки VK Звонков в карточку пользователя. Первая ссылка становится основной для этого пользователя.
3. Выдайте профиль для приложения **FreeTurn** или **WINGS V**. Выбор клиента зависит от сервера и совместимости с протоколом интерфейса. Например, для WINGS V панель не предлагает профиль AmneziaWG 3.1.

На устройстве проверьте подключение и обмен трафиком после импорта. Автообновление серверов FreeTurn и WINGS-N задаётся в настройках TURN. Планируйте перезапуск прокси на время низкой нагрузки.

## Общий пул SOCKS5

Добавьте учётки в **Настройки → Выходы SOCKS5**. Чтобы проверить сохранённый профиль, откройте его редактор, выберите ноду для проверки и нажмите **Проверить с ноды**. В таблице появятся IP выхода, задержка и результат UDP. Выбор ноды действует для этой проверки.

В карточке пользователя выберите одну свободную учётку и действие **Если SOCKS5 недоступен**. Одна учётка применяется ко всем его VPN-устройствам и доступна конечным нодам основной и резервной цепочек. При отсутствии личной учётки рабочая цепочка выпускает трафик с IP своей конечной ноды. Если провайдер разрешает доступ к прокси по списку адресов, добавьте публичные IP обеих конечных нод.

Существующие выходы отдельных нод доступны в блоке **Ранее настроенные выходы на нодах**. При выборе нового профиля в карточке пользователя прежняя привязка снимается. Для старых явно заданных маршрутов нажмите **Использовать общий пул SOCKS5** в настройках правила.

## Маршрутизация

По умолчанию режим **IP** обрабатывает правила по адресам и сетям. **Hybrid SNI** добавляет правила по данным TLS SNI и оставляет клиентский DNS в распоряжении клиента. Имена, скрытые ECH, обрабатываются по IP-правилам. Hybrid SNI отключает QUIC на маршрутах, где требуется анализ TLS SNI.

Режим выхода задаётся отдельно для каждого интерфейса в поле **Маршрутизация интерфейса**.

- **Наследовать правила ноды** использует маршрутизацию из раздела **Настройки → Сеть → нужная нода**. Интерфейсы, ранее настроенные на **Авто (MASQUERADE)**, продолжают наследовать эти правила.
- **Весь трафик напрямую** отправляет трафик через текущую ноду без наследования правил маршрутизации.
- **Свои правила** позволяют задать отдельный набор на каждом интерфейсе. В новых наборах строка **Всё остальное** по умолчанию ведёт напрямую. Выберите в ней **Правила ноды**, если хотите наследовать их для трафика, который не совпал с правилами интерфейса.

Выберите **Через ноды** в правиле или в строке **Всё остальное**. Укажите основную цепочку и при необходимости добавьте одну резервную. Обе цепочки могут включать несколько нод. Для прямого доступа к российским ресурсам задайте **RU → Напрямую (эта нода)**, а цепочки до US1 и US2 добавьте в **Всё остальное**.

Входная нода проверяет доступность интернета через весь путь. При отказе основного пути новые соединения переходят на резерв. Для пользователей с назначенным SOCKS5 обе цепочки проверяются с их учёткой. Если она недоступна по всем путям, настройка **Прямой выход** разрешает трафик с IP рабочей конечной ноды, а **Kill switch** блокирует трафик этой ветки. Если обе цепочки недоступны, трафик ветки блокируется независимо от профиля. При смене внешнего IP открытые соединения могут оборваться.

Для новых цепочек обновите панель и все ноды маршрута. Для служебных IPv4-адресов между нодами используется диапазон `198.18.128.0/17`. DNS-запросы и UDP-трафик, совпавшие с правилом, требуют поддержки UDP у назначенного SOCKS5.

Доступ к разрешённым локальным сетям задаётся отдельно. Интеграции и метрики описаны в [справочнике API](api.md).

Добавьте домены, CIDR или ASN в правило либо сохраните их как свой список для повторного использования. Чтобы искать готовые списки в редакторе, включите нужных провайдеров в **Настройки → Провайдеры гео-данных → Маршрутизация** и сохраните настройку. Выберите **Все**, **IP-сети** или **Домены** в каталоге. Если у списка есть оба типа записей, он доступен в каждом подходящем фильтре.

Поиск учитывает начало слова в названии или коде списка. Например, `RU` находит `Russia` и `category-ru`.

Нода объединяет IPv4-сети источников в пределах одного правила. Источники обновляются независимо. Например, `192.0.2.0/24` покрывает `192.0.2.0/25`, поэтому в итоговом наборе остаётся `/24`. Счётчик в редакторе показывает количество CIDR после объединения загруженных панелью источников. Нода пересчитывает свой набор, когда получает новую версию любого из списков.

Для доменов счётчик показывает покрытие суффиксов. Например, `example.com` уже включает `api.example.com`. Шаблоны имён считаются отдельно. В Hybrid SNI источники с одинаковыми условиями и действием используют общий набор выученных адресов. При совпадении с разными правилами сохраняется приоритет более точного имени.

- **MetaCubeX** содержит домены сервисов и IP-сети, в том числе GeoIP `ru`, GeoSite `category-ru` и `tld-ru`.
- **Re-filter** содержит `community`, `community_ips`, `discord_ips` и большой список `domains_all`.
- **RunetFreedom** содержит GeoSite и GeoIP, включая `ru-available-only-inside` с госресурсами, `ru-blocked` и `ru-whitelist` с IP-сетями из списка мобильного интернета.
- **RoscomVPN** содержит доменные списки, включая `category-ru` и `whitelist` для прямого доступа к российским сервисам.

Панель использует домены с поддоменами и IPv4-сети из этих наборов. Точные имена, ключевые слова и регулярные выражения в GeoSite пропускаются, чтобы сохранить исходные границы совпадения при маршрутизации.

Для прямого выхода к российским ресурсам добавьте в правило с действием **Напрямую (эта нода)** GeoIP `ru` и GeoSite `category-ru` и `tld-ru` от MetaCubeX, `category-ru` и `whitelist` от RoscomVPN и `ru-available-only-inside` от RunetFreedom. Для остальных адресов выберите нужный выход в строке **Всё остальное**. Доменные списки требуют режима с поддержкой доменных правил.

Для маршрута через другую ноду сначала убедитесь, что межнодовая связь работает. При выборочной маршрутизации задайте правила и проверяйте внешний IP на конкретных адресах назначения. Доменные правила Hybrid SNI полезно проверять на новом TLS-соединении. IP-правила можно проверять независимо на адресах из соответствующих списков.

С действием **Всё остальное → Заблокировать** Hybrid SNI проверяет IPv4-правила по порядку. При наличии доменного правила на прямой или удалённый выход нода пропускает TCP-рукопожатие на порту 443 и удерживает данные до проверки видимого имени из ClientHello. Запрещённое или нераспознанное соединение получает TCP RST. Если доменное правило выбирает другой выход, нода сбрасывает первое соединение и использует этот выход, если клиент повторит попытку. Видимое SNI проверяется заново, включая соединения к уже известному IP. Для остального трафика применяются явные IP-правила и действие по умолчанию.

Строки маршрутизации сохраняют порядок и границы. При совпадении доменных правил Hybrid SNI сначала выбирает самое точное имя, а при равной точности учитывает порядок строк.

## Списки блокировок

Откройте **Настройки → Маршрутизация → Блокировки**, нажмите **Новая категория** и добавьте нужные списки. Категории можно подготовить до добавления первой ноды.

Счётчик категории и общий счётчик выбранных блокировок на интерфейсе показывают объединённое покрытие доменов и IPv4-сетей с учётом списка «Никогда не блокировать». IPv4-исключения вычитаются из покрытия даже тогда, когда исключённая подсеть входит в более широкую сеть.

Для корпоративной ноды с Hybrid SNI начните с категории **Угрозы** с HaGeZi TIF Mini. Если нужно ограничить взрослый контент, заведите отдельную категорию с HaGeZi NSFW. Подключайте фильтр рекламы отдельно после проверки рабочих сайтов, авторизации и звонков. Для рекламы достаточно одного списка, например HaGeZi Light. Полный TIF стоит проверять отдельно на ноде с запасом памяти. Он заменяет Mini. Не включайте две версии TIF одновременно.

Включите категорию для входной ноды, сохраните настройки и выберите её на нужных интерфейсах. Переключатель **По умолчанию** задаёт выбор для новых интерфейсов. Для доменных списков используйте Hybrid SNI. Если удалить категорию и сохранить настройки, ноды перестанут применять её при следующей синхронизации.

## Доступ между устройствами и локальные сети

В настройке интерфейса выберите, кто может обращаться к VPN-устройствам по их туннельным адресам. Доступ можно открыть всей ноде, только устройствам того же пользователя либо закрыть. Каждому пиру выдаётся один туннельный адрес для одного устройства.

Доступ к локальной сети самого хоста задаётся в настройках сети ноды.
